# /menu_recommend/ 服务器专用包

本包前端已构建，资源、页面路由、接口及菜单/报告下载均适配 /menu_recommend/。包含 Windows UTF-8 修复。客户无需安装 Node.js 或重新构建。

## 更新已有服务器

1. 停止原应用。备份并保留服务器当前 data 目录，其中包含客户实际数据和菜单历史。
2. 将本包解压到新目录。用服务器原 data 目录替换新目录中的 data；不要用包内示例部署数据覆盖客户现有数据。
3. 保留原 Python 环境或按 backend/requirements.txt 安装依赖。使用原进程管理方式，更新工作目录后运行：
   python run_app.py --host 127.0.0.1 --port 8000 --no-browser
4. 将 nginx-menu-recommend.conf 中两个 location 放入原域名的 server 块，替换原 /menu_recommend/ location，勿重复添加。若后端端口不同，修改 8000。
5. 检查并重新加载 Nginx 配置（nginx -t，确认通过后 nginx -s reload）。
6. 访问 https://客户域名/menu_recommend/ 并强制刷新。

后端仍提供根路径 /api 和 /assets，Nginx 去掉外部 /menu_recommend/ 前缀后转发。不要把后端接口再加一次前缀。

## 验收

- /menu_recommend/ 页面正常。
- /menu_recommend/assets/ 下的 JS、CSS 返回 200。
- /menu_recommend/api/health 返回 JSON。
- /menu_recommend/data-update 刷新正常。
- 确认菜单后，CSV 和理由报告下载正常。

## 重新构建

修改前端后，在 frontend 中执行 npm ci 和 npm run build:server。
npm run build 是根路径版本，会覆盖当前 dist，不适用于客户现有子目录部署。
本包应通过 Nginx 的 /menu_recommend/ 访问；直接打开 8000 根地址不适配此预构建前端。
本包不包含 Python 环境或已安装依赖。首次部署需 Python 3.10–3.12 并安装 backend/requirements.txt。
